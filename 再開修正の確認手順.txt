MOSS Studio 0.1.2 — 再開・追加学習の確認手順

【ホイール操作】
閉じたOptimizer等のドロップダウン上でホイールを回しても、選択値を変更せず
設定ページをスクロールします。選択を変える場合はリストを開いて操作してください。

【プロジェクト管理】
「追加 / コピー」で作成、「削除」で一覧から除外できます。
削除したプロジェクトはdata/projects/_trashへ移動します。
外部のモデル・画像は移動しません。最後のプロジェクトを削除しても再追加できます。

【保存方針】
LoRAは初期値100 STEPごとで、数値は自由に変更できます。
エポックごとにしたい場合はSTEP保存間隔を0、エポック保存間隔を1以上にします。
stateは最新の正常保存1つだけを保持し、正常終了時にも保存します。
新しいstateの保存成功後に古いstateを削除します。LoRAと再開元のstateは削除しません。
この実行以外の過去のstateは自動で整理しません。

【モデル引継ぎ・Caption確認】
デフォルト新規プロジェクトでも、現在のモデル設定を引き継ぎます。
学習設定はデフォルトに戻り、画像フォルダは空欄から始めます。
「画像数・Caption数を確認」で「Caption 認識 N / M 件」を確認してください。
例: image.png と image.txt を同じフォルダに配置します。
「caption なし 0 枚」は未認識ではなく、欠落が0枚という意味です。

【日本語 / English】
ヘッダーの言語選択で切り替えできます。選択言語は次回起動時にも引き継ぎます。
未保存の設定・パス・プロンプトは保持します。導入・学習・環境チェック中は切り替え不可です。
エンジンや導入子プロセスのログは原文、Windowsの標準ボタン等はOSの言語です。

【更新】
アプリを終了し、ZIP内の MOSS-LoRA-Trainer フォルダの内容を、
現在使っているアプリのフォルダへ上書きしてください。
data と backend は同梱していません。削除せず残してください。
venvを作り直したり、install.batを再実行したりする必要はありません。
start.batから起動します。

【確認】
1. 「保存した state から再開…」を開きます。
   下の適用ボタンが表示され、内容が長い場合は上側をスクロールできるか確認します。
2. ずれが発生する前の、保存が完了したstateを選びます。
   「元のモデル・データ・学習設定を復元」をONにして適用します。
3. 元のOptimizer、LRスケジューラ、学習率、STEP / Epoch上限を確認します。
   総上限を変更しない再開は元の学習計画を維持します。上限は手動で拡張できます。
4. 学習開始ログに「cumulative STEP / resume compatibility enabled」が出るか確認します。
   例: STEP 600のstateなら、進捗は600から再開します。
   次のoptimizer更新は601、100 STEPごとの次回保存は700になります。
5. 再保存したstateのtrain_state.jsonでcurrent_stepと保存名のSTEPを確認します。
   総上限を変えた場合、LRは新しい総上限で再計算します。constantなら一定です。

最終stateから続ける場合は、再開ダイアログで総STEP上限を増やしてください。
例: 保存1500 STEP → 総上限3000 STEPで、1500 STEP分を追加します。
Optimizerの状態と累積STEPを保持し、LRを新しい総上限の曲線で再計算します。
Optimizerや学習率等も変える場合は、LoRA重みから新規に始めてください。

【問題が続く場合】
新しい実行フォルダの training.log、train.toml、resume_source.json と、
元のstateの train_state.json を確認に使えます。
既にずれたSTEPで再保存されたstateの履歴は、この修正だけでは復元できません。

【検証範囲】
自動テストと、CPU上のAdamW / Accelerateによる保存・復元を確認しています。
今回の更新は提供者による動作確認済みです。MOSS実モデル・GPU・AdamW8bitによる再開は上記の自動テストの対象外です。
